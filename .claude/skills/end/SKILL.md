# Завершить сессию и передать работу новому чату

Новый чат не видит этот разговор. Всё, что ему нужно, должно лежать в папке проекта, а промпт
для него — называть файлы, точку остановки и первый шаг. История чата — свидетельство,
источник истины — репозиторий.

Навык делает три вещи: записывает состояние в три файла, спрашивает про коммит, выдаёт промпт.

---

## Шаг 1 — Остановиться

Не брать новых задач. Довести до конца только текущее безопасное атомарное действие. Если идёт
долгая операция (сборка, тесты, фоновый процесс) или непонятно, завершилась ли она, — записать
её, а не перезапускать и не отменять ради красивой передачи.

## Шаг 2 — Найти проект и прочитать прежнее состояние

1. Корень проекта: `git rev-parse --show-toplevel`; без Git — рабочая папка сессии.
2. Прочитать `CLAUDE.md` и `docs/SESSION_STATE.md`, `docs/DECISIONS.md`, `docs/TODO.md`.
   Нет файла — создать из одноимённого шаблона в `assets/` этого навыка.
3. Сравнить время изменения `SESSION_STATE.md` с последними правками в проекте. Если он старше —
   это нормально, навык его сейчас перепишет; но старые утверждения из него не переносить без
   проверки.

## Шаг 3 — Проверить фактическое состояние

- ветка и HEAD, `git status --short`, staged и unstaged изменения, неотслеживаемые файлы;
- последние результаты тестов или сборки — с пометкой, к какому состоянию кода они относятся.
  Результат годится только для того кода, на котором его получили; после правок — «не проверено»;
- запущенные процессы, которые видны из сессии.

Чего проверить нельзя — записать как «неизвестно», не угадывать.

## Шаг 4 — Записать состояние

**`SESSION_STATE.md` — переписать целиком** как текущий снимок, не как хронику. Разделы — по
шаблону: цель; проверенное состояние репозитория; что сделано (с артефактами); изменённые файлы;
проверки; неудачные подходы, которые не надо повторять; незавершённые операции; блокеры и
неизвестное; один конкретный `NEXT STEP`.

**`DECISIONS.md` — дописать** только решения, которые ограничивают будущую работу. Старые не
удалять, а помечать «отменено».

**`TODO.md` — обновить** без дублей: выполненное — в «Сделано», следующее — в «Сейчас».

Правила наполнения:

- числа и решения называть, а не описывать: «тесты 42/42 на a1b2c3d», а не «тесты проходят»;
- относительные даты переводить в абсолютные;
- не выдумывать: если за сессию почти ничего не изменилось, так и написать.

Затем перечитать три файла глазами агента, который этот чат не видел. Противоречие с
репозиторием решается в пользу репозитория; неразрешённое — записать явно.

## Шаг 5 — Спросить про коммит

Если рабочее дерево чистое — сказать «коммитить нечего» и перейти дальше.

Если есть изменения — показать `git status --short` и спросить через `AskUserQuestion`:
«Закоммитить изменения?» — **Да** / **Да, коммит и push** / **Нет, оставить как есть**.

- На `main`/`master` сначала предложить ветку.
- Сообщение коммита — по сути изменений, на языке пользователя.
- `--no-verify` не использовать; упал pre-commit — разобраться, а не обходить.

Без ответа пользователя не коммитить, не пушить, не откатывать файлы и не останавливать процессы.
Спросить не получается (нет `AskUserQuestion`, неинтерактивный запуск) — ничего не коммитить,
записать изменения как незакоммиченные и перейти к шагу 6: промпт нужен в любом случае.
Незакоммиченная работа — нормальное состояние для передачи: описать staged, unstaged и
неотслеживаемое отдельно.

## Шаг 6 — Собрать промпт для нового чата

Промпт вставят первым сообщением в чистый чат. Писать от лица пользователя, во втором лице
(«прочитай», «начни»).

```text
<Проект> — <что за работа>. Продолжаем.

Перед первым действием прочитай по порядку:
1. <полный путь>/CLAUDE.md — правила проекта
2. <полный путь>/docs/SESSION_STATE.md — где остановились
3. <полный путь>/docs/DECISIONS.md — принятые решения
4. <полный путь>/docs/TODO.md — очередь задач
5. <рабочий файл, если есть> — <зачем, одной строкой>

Ветка <ветка>, HEAD <коммит>, <чисто / что не закоммичено>.

Где остановились: <3–5 строк с числами и решениями.>

Не повторять: <неудачные подходы; нет — строку убрать.>

Открытые вопросы: <то, что решает пользователь, а не агент; нет — строку убрать.>

Сверь файлы с Git и папкой проекта, коротко ответь «Recovered / Current state / Next»
и начни с <один конкретный первый шаг>.
```

- Пути — полные: относительные в новом чате не разрешаются.
- Каждый путь проверить на существование перед вставкой.
- У каждого файла — одна строка «зачем».
- Вопросы к пользователю отделять от задач.
- Не пересказывать содержимое файлов, которые и так названы к прочтению: промпт — оглавление,
  не конспект. До 25 строк; не влезает — лишнее должно лежать в `SESSION_STATE.md`.

Сохранить промпт в `docs/NEXT_PROMPT.md` (файл производный, перезаписывается каждый раз).

## Шаг 7 — Ответ пользователю

По порядку:

1. Какие файлы обновлены.
2. Git: закоммичено / оставлено / без изменений; что осталось непроверенным.
3. Промпт — одним блоком ```` ```text ````, чтобы копировался целиком.
4. Строка `SESSION READY FOR HANDOFF`.
5. Одна строка: «Наберите `/clear` (или откройте новый чат) и вставьте промпт».

Новый чат сам не открывать и не утверждать, что он открыт: когда переходить, решает пользователь.

Когда нужен не новый чат, а `/compact`, — см. [context-policy.md](references/context-policy.md).

## Частые ошибки

| Ошибка | Как правильно |
|---|---|
| Старый PASS выдан за текущий | Указать коммит, на котором прошли тесты; после правок — «не проверено» |
| Незакоммиченные файлы не упомянуты | Перечислить staged, unstaged и неотслеживаемые отдельно |
| Перезапущена операция с неясным статусом | Записать её и сделать проверку статуса первым шагом |
| В промпте «продолжить работу» | Один исполнимый шаг и что проверить перед ним |
| Промпт пересказывает сессию | Ссылки на файлы; пересказ живёт в `SESSION_STATE.md` |
| В промпт попали служебные идентификаторы сессии | Убрать: новому чату они не нужны |
